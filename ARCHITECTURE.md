## Поток данных

### 1. Аутентификация

```
Клиент                          Сервер
  │                                │
  │  POST /api/auth/register       │
  │  {email, password, username}   │
  │───────────────────────────────►│
  │                                │  Проверка в БД
  │                                │  Хэширование пароля (bcrypt)
  │                                │  Создание пользователя
  │                                │  Генерация JWT токенов
  │  {access_token, refresh_token} │
  │◄───────────────────────────────│
  │                                │
```

### 2. Подключение к голосовому каналу (P2P режим)

```
Клиент A         Сервер          Клиент B
  │                 │                │
  │  Join channel   │                │
  │────────────────►│                │
  │                 │                │
  │                 │  Notify B      │
  │                 │───────────────►│
  │                 │                │
  │  ◄───── WebRTC Signaling (через WebSocket) ─────►  │
  │         (SDP offer/answer, ICE candidates)         │
  │                 │                │
  │  ◄═══════ P2P Audio (WebRTC) ═══════════════════►  │
  │              (напрямую между клиентами)            │
  │                 │                │
```

### 3. Подключение к голосовому каналу (SFU режим)

```
Клиент A         Сервер          Клиент B
  │                 │                │
  │  Join channel   │                │
  │────────────────►│                │
  │                 │                │
  │  WebRTC         │  WebRTC        │
  │  connection     │  connection    │
  │────────────────►│◄───────────────│
  │                 │                │
  │  ═══ Audio ═══►│                │
  │                 │══ Audio ═════►│
  │                 │                │
  │                 │◄══ Audio ═════│
  │◄══ Audio ══════│                │
  │                 │                │
```

## Режимы работы

### P2P Mesh (для малых групп)

**Когда использовать:** 2-6 участников

**Преимущества:**
- ✅ Минимальная задержка (прямое соединение)
- ✅ Нет нагрузки на сервер
- ✅ Работает даже если сервер недоступен (после установки соединения)

**Недостатки:**
- ❌ O(n²) соединений (6 пользователей = 30 соединений)
- ❌ Высокая нагрузка на upload каждого клиента
- ❌ Не масштабируется

**Архитектура:**
```
    A ←→ B
    ↕ ↕ ↕
    C ←→ D
```

### SFU (для больших групп)

**Когда использовать:** 5+ участников

**Преимущества:**
- ✅ O(n) соединений
- ✅ Низкая нагрузка на клиенты
- ✅ Масштабируется до 100+ участников
- ✅ Централизованное управление

**Недостатки:**
- ❌ Дополнительная задержка (через сервер)
- ❌ Нагрузка на сервер
- ❌ Требует TURN сервер для NAT traversal

**Архитектура:**
```
    A → SFU → B
    C → SFU → D
    E → SFU → F
```

## Компоненты

### Frontend (React + TypeScript)

**Расположение:** У пользователя (браузер или desktop app)

**Функции:**
- UI (интерфейс пользователя)
- Захват микрофона (Web Audio API)
- WebRTC (P2P или SFU)
- WebSocket клиент
- JWT аутентификация
- Desktop интеграция (Tauri)

**Технологии:**
- React 18
- TypeScript
- Vite
- Tailwind CSS
- WebRTC API
- WebSocket API

### Backend (Go)

**Расположение:** На вашем VPS

**Функции:**
- REST API (аутентификация, серверы, каналы)
- WebSocket сервер (сигнализация для P2P)
- SFU сервер (Pion WebRTC)
- JWT токены
- Управление комнатами

**Технологии:**
- Go 1.21+
- gorilla/websocket
- Pion WebRTC
- golang-jwt
- bcrypt

### Database (PostgreSQL)

**Расположение:** На вашем VPS (или отдельный сервер)

**Функции:**
- Хранение пользователей
- Хранение серверов и каналов
- Хранение сообщений
- Хранение refresh токенов

**Технологии:**
- PostgreSQL 15
- SQL миграции

### TURN Server (Coturn)

**Расположение:** На вашем VPS

**Функции:**
- NAT traversal для WebRTC
- Relay медиа-трафика
- Обязателен для работы через интернет

**Технологии:**
- Coturn
- STUN/TURN протоколы

## Сетевые требования

### Порты

| Порт | Протокол | Назначение |
|------|----------|------------|
| 22 | TCP | SSH (администрирование) |
| 80 | TCP | HTTP (редирект на HTTPS) |
| 443 | TCP | HTTPS (frontend + API) |
| 3478 | TCP/UDP | TURN сервер |
| 5432 | TCP | PostgreSQL (только localhost) |
| 8080 | TCP | Go backend (только localhost) |

### Firewall правила

```bash
# Разрешить SSH
ufw allow 22/tcp

# Разрешить HTTP/HTTPS
ufw allow 80/tcp
ufw allow 443/tcp

# Разрешить TURN
ufw allow 3478/tcp
ufw allow 3478/udp

# Запретить прямой доступ к БД и backend
# (только через Nginx reverse proxy)
```

## Безопасность

### Аутентификация

- **Пароли:** bcrypt хэширование (cost factor 10)
- **JWT токены:** HMAC-SHA256 подпись
- **Access token:** короткоживущий (24 часа)
- **Refresh token:** долгоживущий (7 дней), хранится в БД

### Транспорт

- **HTTPS:** обязательный для продакшна (иначе нет доступа к микрофону)
- **WSS:** WebSocket over TLS
- **TLS 1.2+:** минимальная версия

### CORS

- Настроен на конкретные домены
- Запрещены произвольные origins

### Rate Limiting

- Рекомендуется настроить на Nginx
- Защита от brute force атак

```
1 CPU, 1 GB RAM  →  до 50 пользователей
2 CPU, 4 GB RAM  →  до 200 пользователей
4 CPU, 8 GB RAM  →  до 500 пользователей
```

### Горизонтальное (больше серверов)

```
┌──────────┐
│   LB     │  ← Load Balancer (Nginx/HAProxy)
└────┬─────┘
     │
     ├────► Backend #1
     ├────► Backend #2
     └────► Backend #3
     
     └────► PostgreSQL (Master-Slave)
```

## Резервное копирование

### Что бэкапить

1. **PostgreSQL база данных**
   ```bash
   pg_dump -U voicehub voicehub > backup.sql
   ```

2. **Конфигурационные файлы**
   - `server/.env`
   - `/etc/nginx/sites-available/voicehub`
   - `/etc/turnserver.conf`

3. **SSL сертификаты**
   - `/etc/letsencrypt/`

### Автоматический бэкап

```bash
# Добавить в cron (ежедневно в 3:00)
0 3 * * * /root/backup.sh
```
